## 2. 🔴 KRİTİK

### K-1. Public API SMTP parolunu və AI açarını sızdırırdı

**Fayl:** `apps/api/controllers/publicController.js` — `getSite`, `getHome`
**Vəziyyət:** ✅ **Audit zamanı düzəldildi**

`/api/site` autentifikasiya tələb etmir və bütün `SiteSetting` sənədini qaytarırdı:

```
Public /api/site cavabındakı açarlar:
  brand, contact, socials, hero, seo, codeInjection, smtp, ai, ...
  smtp: ["enabled","host","port","secure","user","pass","fromName","fromEmail"]
  ai:   ["enabled","apiKey","model"]
```

Admin tərəfdə maskalama var idi (`adminController.getSettings` → `pass: ""`), amma **public tərəfdə yox idi**. Yəni:

> Sən Tənzimləmələr → AI-də OpenRouter açarını yazan kimi, `http://<sayt>/api/site` ünvanına girən **hər kəs** onu oxuya bilərdi. SMTP parolu üçün də eyni.

Sınaq anında sahələr boş idi (heç nə konfiqurasiya olunmamışdı), ona görə **faktiki sızma baş verməyib** — amma açar yazılan an aktivləşəcəkdi.

**Düzəliş:**

```js
const PRIVATE_SETTING_FIELDS = ["smtp", "ai"];

function publicSettings(doc) {
  const out = typeof doc?.toObject === "function" ? doc.toObject() : { ...doc };
  for (const f of PRIVATE_SETTING_FIELDS) delete out[f];
  return out;
}
```

Həm `getSite`, həm `getHome` bundan keçir. `robotsTxt` qəsdən saxlanılıb — `/robots.txt` route-u onu public `getSiteSettings()` vasitəsilə oxuyur.

**Test:** vahid test — `SUPER-SECRET` və `sk-or-v1-SECRET` cavabda yoxdur, `robotsTxt` qalır. ✅

**Tövsiyə:** Bu sahələr artıq bazada varsa, açarları **rotasiya et** (dəyiş) — köhnəsi keşlərə düşmüş ola bilər.

## 3. 🟠 YÜKSƏK

### Y-1. `codeInjection` ölü funksiyadır — saxlanılır, heç vaxt render olunmur

**Fayllar:** `siteSetting.model.js:77`, `tenzimlemeler/page.js:347`
Admin paneldə `<head>` və `</body>` kodu üçün iki sahə var, DB-yə yazılır — amma `apps/web` tərəfində **heç yerdə render olunmur** (bütün `src` qrep edildi: yalnız settings səhifəsində, yəni öz formasında).

Nəticə: analytics/pixel əlavə etmək istəyən müştəri kodu yazır, «Yadda saxlanıldı» görür, **amma sayta heç nə düşmür**. Bu, PDF tələblərindən biridir.

**Düzəliş:** `app/layout.js`-də `getSiteSettings()`-dən oxuyub `<head>`-ə və `<body>` sonuna inject etmək. Diqqət: bu, admin/editor-a **saytda ixtiyari skript icra etmək** imkanı verir — ona görə yalnız `admin` rolu redaktə edə bilməlidir (bax Y-4).

### Y-2. 500 KB şəkil limiti (müştəri tələbi) tətbiq olunmur

**Fayllar:** `siteSetting.model.js:87` (`maxImageSizeKb: 500`) vs `middlewares/upload.js` + `config.upload.maxImageSize` (**30 MB**)

Admin paneldə limit görünür və redaktə olunur, amma yükləmə marşrutu `config`-dən oxuyur — DB dəyəri **heç vaxt oxunmur**. 30 MB şəkil problemsiz yüklənir.

**Düzəliş:** `uploadLimit` middleware-ini `SiteSetting.get()`-dən oxuyacaq şəkilə gətir (SMTP/AI ilə eyni ENV-fallback məntiqi).

**Düzəliş:** paylaşılan `<QueryState isLoading isError onRetry>` komponenti (bax §6).

### Y-4. `editor` rolu SMTP parolunu və AI açarını dəyişə bilir

**Fayl:** `routes/adminRoutes.js:25` — `PUT /admin/settings` yalnız `requireRole(["admin","editor"])` ilə qorunur.

`devController` və `userAdminController` düzgün şəkildə `role !== "admin"` yoxlayır, amma **settings yoxlamır**. Editor:
- SMTP-ni öz serverinə yönləndirə (bütün lead bildirişlərini oğurlaya) bilər,
- OpenRouter açarını oxuya (yox — indi maskalanır) / dəyişə bilər,
- `codeInjection` işə düşəndə (Y-1) saytda ixtiyari skript icra edə bilər.

**Düzəliş:** `updateSettings`-ə `if (req.user?.role !== "admin")` yoxlaması; və ya sahə səviyyəsində — editor `contact`/`hero` dəyişsin, `smtp`/`ai`/`codeInjection` yalnız admin.

Eyni məntiq: `POST /admin/whatsapp/bulk` — editor bütün müraciətlərə şirkət nömrəsindən kütləvi mesaj göndərə bilər.

## 4. 🟡 ORTA

### O-1. `dest.flag` — public saytda sanitizasiyasız HTML

**Fayl:** `components/site/cards.jsx:49`

```jsx
<span className="ba-flag" dangerouslySetInnerHTML={{ __html: dest.flag }} />
```

`flag` modeldə sərbəst `String`-dir («Inline SVG or asset path»), admin JSON redaktorundan istənilən dəyər yazıla bilər. Editor rolu `<img src=x onerror=...>` yazsa — **saxlanmış XSS**, ana səhifədə və xaricdə-təhsil səhifəsində bütün ziyarətçilərə işləyir.

**Düzəliş:** ya `DOMPurify.sanitize(dest.flag, { USE_PROFILES: { svg: true } })`, ya da sahəni emoji/URL ilə məhdudlaşdır.

### O-2. Admin forma önizləmələrində sanitizasiya yoxdur

TiptapEditor-un öz önizləməsi (`TiptapEditor:454`) `sanitizeHtml` işlədir, formalar isə yox. Admin öz məzmununu görür, risk aşağıdır, amma **defense-in-depth** üçün eyni helper işlədilməlidir.

### O-6. `User.password` sahəsində `select: false` yoxdur

**Fayl:** `models/user.model.js:23` — `toJSON` transform da yoxdur. Hazırda bütün cavab yolları ağ siyahı işlədir (`toUserResponse`, `userAdminController` mapper), yəni **aktiv sızma yoxdur** — amma bir dənə diqqətsiz `res.json({ user })` bcrypt hash-ini açar.

### O-7. WhatsApp media limiti UI ilə uyğun gəlmir

`send-media` base64-ü JSON body-də qəbul edir, body limiti isə **10 MB** (`config.securityConfig.maxPayloadSize`). Base64 ~33% şişirdir → real limit **~7.5 MB**. MediaForm isə «video ≤100MB» yazır. 20 MB video 413 ilə düşəcək və səbəb aydın olmayacaq.

**Qeyd:** `send-media` endpointi hazırda frontend-də istifadə olunmur (yalnız API-də mövcuddur).

`siteSetting.model.js:84` — modeldə var, admin UI-da yoxdur, frontend-də oxunmur. Ya tətbiq et (Organization JSON-LD ilə birləşdir), ya sil.

## 8. Responsivlik

**✅ Yaxşı işləyən:**
- Public sayt: `globals.css`-də tam media query dəsti — `grid-2/3/4/5/6` → 1024px-də 2 sütun, 760px-də 1 sütun; `.split` → 1fr; `.ba-wall` columns 3→2→1; `.ba-pricegrid` → 1fr
- Maskotlar 1100/860/680px-də kiçilir və gizlənir
- `prefers-reduced-motion` 4 yerdə hörmət olunur
- Admin modalları: `w-full max-w-2xl` + `p-4` gutter + `max-h-[92vh]`
- Navbar: mobil çekmecə, iç-içə açılan menyu

**❌ Problemlər:**
1. **4 admin cədvəli** — `overflow-x-auto` yoxdur (O-5)
2. **WhatsApp QR** — `h-72 w-72` (288px) + `p-8` (64px) = 352px; 320px ekranda daşır
3. **Pairing kod** — `text-3xl tracking-[0.3em]` 8 rəqəm ≈ 300px, dar ekranda sıxılır
4. **`muracietler`** — `w-64` axtarış + `w-48` filtr yan-yana; `flex-wrap` var, amma 360px-də iki sətir olur (qəbul edilən)
5. **WhatsApp status zolağı** — 4 element `flex-wrap` ilə, mobil dikey yığılır (qəbul edilən)

**Tövsiyə:** QR üçün `h-56 w-56 sm:h-72 sm:w-72`, pairing kod üçün `text-xl sm:text-3xl`.

| Admin cədvəl sətirləri | siyahı yüklənəndə stagger `fade-in-up` (50ms addım) |
| Toplu göndəriş progress | progress bar-a `transition-[width] duration-500` (indi ani sıçrayır) |
| Modal açılışı | `scale(.96) → 1` + fade (indi ani görünür) |
| Toast/notify | sağdan sürüşmə + çıxışda fade |
| Tab keçidi | aktiv tab altında sürüşən indikator (`layoutId` naxışı) |
| Rəqəmlər (statistika) | ekrana girəndə 0-dan hədəfə sayma |
| Kurs kartları | hover-də şəkil `scale(1.04)` (bloqda var, kurslarda yoxdur) |
| Skeleton | «Yüklənir…» mətni yerinə boz skeleton sətirlər |
| QR görünüşü | QR gələndə `scale-in` + yumşaq parıltı |
| Dil dəyişimi | hard reload — keçid ekranı əlavə oluna bilər |

**Vacib:** hər yeni animasiya `@media (prefers-reduced-motion: reduce)` ilə söndürülməlidir — layihədə bu vərdiş artıq var, pozulmasın.
